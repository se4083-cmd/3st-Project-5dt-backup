CS Flow AI — 분류·검토 신호 점검 (2026-11-02, v3)

1. 준비
ZIP 안의 classify_with_signals.py, check_signals.py, signal_cases.json을
기존 csflow-openai 폴더에 복사합니다. 같은 이름의 파일은 이번 수정본으로 교체합니다.
기존 classify_inquiry.py, test_openai.py, .env와 같은 위치입니다.
새 패키지 설치는 필요하지 않습니다.
VS Code에서 기존 .venv를 활성화하고, 앞서 사용한 계정으로 az login한 상태로 실행합니다.

2. 실행
목록만 확인: python .\check_signals.py --list
16건 실행: python .\check_signals.py
앞의 4건만 실행: python .\check_signals.py --limit 4
실패한 4건 재점검: python .\check_signals.py --cases S02 S10 S12 S14
남은 S10만 점검: python .\check_signals.py --cases S10

우선 S10 한 건으로 수정안을 점검합니다. 그다음 이전 실패 4건과 전체 16건에서
다른 사례가 나빠지지 않았는지 확인합니다. 사례와 기대 정답은 수정하지 않았습니다.
--cases와 --limit은 동시에 사용하지 않습니다.

--list는 API를 호출하지 않습니다.
일반 실행은 제공된 합성 문의마다 API를 1회씩 순차 호출합니다.
기존 gpt-5-mini 배포와 인증 설정을 사용하므로 실행 시 API 사용량이 발생합니다.
재시도와 병렬 실행은 하지 않습니다. HTTP/연결/인증 오류가 나면 남은 호출을 중단합니다.
출력이 잘못되면 오류로 기록합니다. Ctrl+C로 중단해도 완료된 시도는 저장됩니다.
결과 저장에 실패했다면 이후 호출을 진행하지 않습니다.

3. 비교하는 항목
- 문의 유형이 기대값과 같은지
- 태그 집합이 기대값과 같은지 (순서 무관)
- review_required가 기대값과 같은지
- 태그마다 원문에 실제로 존재하는 근거가 하나씩 있는지

요약의 사실 일치와 근거의 의미 적절성은 자동 채점하지 않습니다.
예: 근거가 원문에 있어도, 그 문장이 해당 신호를 뒷받침하는지는 별도 검토합니다.
결과 JSON에는 각 사례의 검토 유의사항과 NOT_REVIEWED 표시가 있습니다.
전체 일치는 위 자동 비교 항목의 통과만 뜻합니다.
이 사례들은 개발용이며 독립 평가용 데이터가 아닙니다.

4. 결과 파일
check_results\signal_check_날짜_시각_UTC.json
각 시도 후 진행 상태를 저장하고 종료 시 집계를 갱신합니다.
기대값/실제값, 요약/원문 근거, 토큰 사용량(확보된 경우), 소요 시간,
배포 이름, 실제 응답 모델, 프롬프트 버전, 코드·프롬프트·스키마 해시를 기록합니다.
콘솔에도 각 태그의 원문 근거를 출력합니다.
추론 강도와 출력 토큰 한도를 기록하고, API가 제공하면 추론 토큰 수도 표시합니다.
추론 토큰은 출력 토큰에 포함되므로 출력 토큰에 다시 더하지 않습니다.
오류 응답 등에서 토큰 사용량을 얻지 못한 경우 합계가 전체 사용량을 뜻하지 않습니다.
토큰이 보고되지 않은 시도 수는 attempts_without_usage로 기록합니다.
계정 이메일, 인증 토큰, API 키, .env 내용이나 전체 오류 본문은 기록하지 않습니다.
제공된 합성 사례만 사용하세요.

5. 현재 단계의 범위
review_required=false는 자동 처리 승인이나 반품·환불 승인 값이 아닙니다.
실제 사람 이관·고객 메시지 발송·반품·환불·계정 조치는 실행하지 않습니다.
영문 분류·태그 코드는 팀 통합 전 확정할 개발 초안입니다.
사진 분석·첨부파일 접수·정책 조회·RAG 연동은 포함하지 않습니다.
실서비스의 직접 사람 연결 요청은 모델 호출 앞에서 우선 처리해야 합니다.

6. 이번 수정
프롬프트 버전: signals_draft_v3
일반적인 확인·안내 요청과 실제 사람 연결 요청을 구분하는 조건을 보강했습니다.
연결 거절, 예외 요청 부정, 설명 속 인용을 구분하는 예시를 추가했습니다.
원문에 없는 사람 연결 대상을 보충하지 않도록 근거 조건을 보강했습니다.
같은 모델을 사용하며 추론 강도는 minimal에서 low로 높였습니다.
추론 토큰을 포함한 출력 토큰 한도는 1,000에서 2,000으로 높였습니다.
한도는 고정 사용량이 아니며, 실제 토큰 사용량과 응답 시간은 늘어날 수 있습니다.
기존 태그 코드와 기대 정답은 유지합니다.
키워드 규칙으로 모델 결과를 덮어쓰지 않습니다.
수정 파일의 실행 동작은 모의 응답으로 확인하며,
실제 모델의 오탐 개선 여부는 사용자가 API 재점검을 실행한 결과로 확인합니다.
