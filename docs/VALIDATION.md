# v2.1 실행 검증 기록 · 2026-11-04

## 직접 실행한 결과

검증 환경은 Linux, Node.js 24.22.1, npm 11.9.0 및 Chrome이다. 기존 Site의 의존성 경로를 참조하지 않는 빈 설치 폴더에서 `npm ci`를 실행했다. npm registry를 사용하는 독립 package-lock이며 로컬 외부 폴더 link는 없다.

| 구분 | 결과 |
| --- | --- |
| 독립 의존성 설치 | 통과 |
| TypeScript `npm run check` | 통과 |
| 전체 자동 검사 `npm test` | **162개 통과, 실패·건너뜀 0개** |
| RAG corpus `npm run rag:check` | 개발용 문서 10개, 무결성 통과 |
| 프로덕션 빌드 `npm run build` | 통과 |
| 빌드 실행 검사 `npm run verify:build` | SPA 경로·정적 자산 4개·API 상태 통과 |
| PDF | 8페이지 전체 렌더 검토, 텍스트 넘침 0, 최소 11.5pt |

162개는 이번 소스에서 한 번 실행한 자동 검사 수다. 다른 브랜치, 이전 버전, 문서에 적힌 과거 검사 수를 더하지 않았다.

검색 정확도 100%나 일반 고객 문의 전체에 대한 성능 수치로 해석하지 않는다. 작은 개발용 corpus와 허용 질문군에 대한 동작·경계 검사다. 새롭지만 안전한 표현도 허용 범위로 확인하지 못하면 사람 검토로 보낼 수 있다.

## 브라우저에서 확인한 사용자 흐름

- 고객이 FAQ를 자신의 문장으로 접수하고, 검색 근거의 자동 답변을 확인했다.
- 새로고침과 서버 재시작 후 문의·답변이 유지되는 것을 확인했다.
- 환불 승인 요청이 사람 큐로 이동하고 인수 → 초안 수정 → 승인 → 답변 확정으로 처리되는 것을 확인했다.
- 자동화 중지 → 10개 상태 엔진 회귀 검사 → 명시적 재개를 확인했다.
- 준비된 후속을 진행 → 완료로 변경하고, 저장 및 미완료 목록 갱신을 확인했다.
- 운영 설정에서 배송 문서 검색·근거 문안·후보를 확인했고, 배송 상태와 주소 변경을 함께 요청하면 자동 문안을 만들지 않는 것을 확인했다.
- 제품 P1 사전 작성 제안과 P2 이력 부족 표시를 확인했다.
- 제품의 관련 문의에서 완료된 특정 문의로 정확히 이동하고, 해당 제품 후속에서 특정 후속 ID만 표시하는 것을 확인했다.

## 한계와 보존

Windows 안내와 실행 파일을 제공하지만 Windows OS에서 직접 실행한 검증은 아니다. 실제 JWT 로그인, 팀 FastAPI/PostgreSQL worker, 외부 고객 발송, 운영 RAG·임베딩·OpenAI API·Fabric 연결은 이번 검사에 포함하지 않는다. 앱의 외부 모델 호출은 0회다.

대상은 별도 v2 개발 프로젝트이며 기존 v1 Site와 팀 브랜치를 수정하지 않았다. 3개 분석 데이터 파일의 원본 바이트를 유지한다. 기존 30개 비활성 합성 정책과 73개 승인 대기 KB를 활성화하거나 프로젝트에 복사하지 않았다.

빌드의 500KB chunk 안내는 합성 분석 데이터가 포함된 번들에 대한 크기 경고이며 빌드는 성공했다. 문서 저장소 파일 편집과 PostgreSQL의 운영 동시성은 별도 통합 검증이 필요하다.
