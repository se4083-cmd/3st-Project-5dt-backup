# CS Flow AI · React Frontend / Week 01

2026-11-03. E-commerce Manager 운영 스토리보드 v2와 공개 시연의 디자인을 React 컴포넌트로 옮긴 **1주차 개발 프로젝트**입니다. 기존 공개 사이트와 데이터 파이프라인은 변경하지 않았습니다.

## 실행

Node.js 22.12 이상과 npm을 사용합니다. 설치 버전은 `package-lock.json`에 고정되어 있습니다.

```powershell
cd frontend
npm ci
npm run dev
```

터미널의 Local 주소를 여세요. 기본 주소는 `http://127.0.0.1:5173/`입니다. 다른 PC가 이 주소로 접속할 수 있는 것은 아닙니다.

```powershell
npm test
npm run build
npm run preview
```

기술 구성: React + TypeScript + Vite, React Router의 HashRouter, 일반 CSS. API 호출은 기본 fetch, 단위/컴포넌트 검증은 Vitest + Testing Library입니다. 별도 전역 상태·차트·UI 라이브러리는 추가하지 않았습니다.

## 1주차 구현

- **공통 UI:** AppShell, 5개 메뉴, PageHeading, AsyncState, Badge, DataTimestamp, TicketList, 업무 카드.
- **운영 홈:** 우선 확인할 문의, 현재 업무 4종, 후속 업무 수, 별도 분석 기준 시각·분모가 있는 기간 KPI.
- **화면 상태:** 정상 / 로딩 / 정상 0건 / 통신 오류 / 401·403·404·409·422·429·503 / 분석 미집계 / 이전 정상 분석.
- **권한 표시:** 활성 ADMIN + 명시적 기능 권한 + 허용 팀 확인. 메뉴 숨김과 직접 경로 검사를 함께 적용합니다. Manager는 UI 역할 이름이며 추가 권한이 아닙니다.
- **데이터 수명:** 프로필·범위·재조회 변경 시 이전 데이터를 즉시 숨기고 진행 중 요청을 취소합니다. 늦게 도착한 이전 요청도 무시합니다. 보호 데이터·토큰을 localStorage/sessionStorage에 보관하지 않습니다.
- **A/B 연동 경계:** 개발용 응답과 HTTP client를 분리했습니다. HTTP 연결 정보가 없으면 차단하고, 오류 시 합성 데이터로 자동 대체하지 않습니다.
- **연결 화면:** 문의 필터와 선택 ID를 URL로 전달합니다. 문의 처리·후속·제품·운영 설정은 개발 예정 주차를 표시하는 연결 화면이며, 완료된 업무 기능으로 표시하지 않습니다.

## 직접 확인할 순서

1. 운영 홈의 `검토 대기 4건`을 선택 → 문의 경로와 `REVIEW` 조건 유지 확인.
2. 상단 `개발용 상태 시연`을 펼쳐 로딩, 빈 결과, 통신 오류와 상태 코드를 선택.
3. `분석 미집계` 선택 → 현재 업무는 유지되고 KPI만 미집계 표시.
4. `이전 정상 분석` 선택 → 분석 기준 시각과 이전 정상 결과 안내 유지.
5. `배송팀 Manager` 선택 → 검토 1건/T-2403만 표시, 운영 설정 메뉴 숨김.
6. 같은 프로필로 `#/settings` 직접 진입 → 권한 오류 확인.
7. `고객` 또는 `비활성 계정` 선택 → 운영 데이터 제거.
8. `로그아웃` 선택 → 인증 안내 → `시연 로그인 복구`로 초기 프로필 복구.

상단 선택기는 **개발용 프로필 시뮬레이터**입니다. 실제 로그인이나 권한 변경이 아닙니다. 초기 업무 시각은 스토리보드와 일치하도록 2026-11-02 10:00 KST로 고정했습니다. 합성 데이터에 실제 고객 정보를 입력할 기능은 없습니다.

## 실제 API로 전환

`.env.example`을 `.env.local`로 복사하고 `VITE_DATA_MODE=http`로 지정합니다. `VITE_SESSION_PATH`, `VITE_OVERVIEW_PATH`에는 **백엔드와 합의한 동일 출처 `/api/...` 경로**만 넣습니다. 확인되지 않은 `/me`·운영 홈 API를 임의로 구현된 경로로 간주하지 않습니다.

현재 HTTP adapter는 **동일 출처 세션/BFF 방식의 제안 구현**입니다. 기존 기획의 로그인 API는 JWT를 반환하지만, 실제 로그인·토큰 갱신·세션 조회 계약은 아직 연결하지 않았습니다. 백엔드 팀이 쿠키/BFF 또는 JWT 전달 방식을 확정한 후 해당 adapter를 변경해야 합니다. 지금 HTTP 모드를 켠 것만으로 로그인되는 것은 아닙니다.

모든 `VITE_*` 값은 브라우저에 공개됩니다. 서비스 토큰, 모델/Search 키, DB 암호, 기존 파이프라인의 reader/publisher 토큰을 넣지 마세요. 서버는 매 요청마다 역할·활성 계정·허용 팀·개체 범위를 검증해야 합니다. UI의 `can()`은 서버 보안을 대신하지 않습니다.
